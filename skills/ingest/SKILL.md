너는 원본 문서 하나를 위키에 반영한다. 원본은 고치지 않는다(R1). 고칠 수 있는 곳은 `wiki/` 아래뿐이다(`wiki/log.md` 제외).

## 받는 정보

프롬프트에 대상 원본 경로와, 이번 실행에서 앞서 반영한 원본 목록이 들어 있다. 원본은 파일명 날짜 순서로 하나씩 온다.

## 순서

1. **분석부터 한다. 분석 전에 파일을 고치지 않는다.** 원본을 읽고 아래를 정리한다.
   - 이 문서가 새로 정하는 것
   - 이 문서가 뒤집는 기존 결정이나 약속(무엇을 대체하는지)
   - 기존 위키와 부딪히는 서술(어느 페이지의 어느 내용과 다른지)
   - 이 문서로 해소되는 열린 항목
   - 영향을 받는 페이지 목록
   - 이번 실행에서 앞서 반영한 원본과의 관계(같은 주제를 이어받는지, 뒤집는지)
2. 원본이 `raw/2026-10-07-회의록.md`이면 `wiki/sources/2026-10-07-회의록.md`를 만든다. 파일 이름은 원본과 똑같고 `.md`를 또 붙이지 않는다. 요약과 `affects` 목록을 적는다. `raw`에는 `2026-10-07-회의록.md`처럼 파일명만 쓰고 `raw/` 접두를 붙이지 않는다.
3. **결정**을 반영한다.
   - 새 결정은 `decisions/YYYY-MM-DD-<제목>.md`로 만든다. 날짜는 원본 파일명의 날짜다. 아직 확정이 아니면 `status: 논의 중`이다. 새 결정의 `sources`에는 이번 대상 원본의 파일명을 넣는다(`raw/` 접두 없이).
   - 기존 결정을 뒤집으면 R3대로 옛 페이지를 `대체됨`으로 바꾼다.
   - **구성요소를 없애는 결정이면 R7을 따른다.** 없어지는 저장소의 코드 사본을 읽어 하던 일을 표로 뽑고, 새 담당이 없는 일을 `open-questions.md`에 올린다.
4. 원본이 저장소 사이 인터페이스를 정하면 이미 있는 `contracts/` 페이지의 본문 서술만 고친다. 그 페이지의 `evidence`는 건드리지 않는다. 코드와 다르면 R4를 따른다.
   - 코드 근거 없이 문서에만 나오는 인터페이스는 새 `contracts/` 페이지를 만들지 않는다. 결정 페이지에 적거나 `open-questions.md`에 `종류: 미정`으로 올린다.
   - `저장소@커밋:경로` 근거를 지어내지 않는다.
5. 해소된 열린 항목은 R5대로 옮기고 지운다. 원본만으로 판단할 수 없는 내용은 `종류: 미정`으로 올린다.
6. 새 페이지를 만들었으면 `index.md`에 추가한다. 고친 페이지의 `updated`를 작업 요청 프롬프트의 `오늘 날짜:` 줄 값으로 바꾼다. 날짜를 추측하지 않는다.

## 재확인 요청일 때

프롬프트가 "재확인"을 요청하면 새 원본을 반영하지 않는다. 대신 받은 목록(이번 실행에서 바뀐 결정·약속)에 기대는 페이지를 찾아 다시 읽는다. 앞서 "현행"이나 "확정"이라고 쓴 서술이 뒤 문서 때문에 낡았으면 고친다.

## 응답 마지막

응답 맨 끝에 `## 문서 분석` 절을 쓴다. PR 본문에 그대로 들어간다. 상자 안의 내용을 `##` 제목부터 그대로, 상자 표시(```) 없이 응답에 쓴다. 상자는 형식 예일 뿐이다.

```
## 문서 분석
- 새로 정함: …
- 대체: …
- 충돌: …
- 해소: …
- 영향 페이지: …
- 확신이 낮은 부분: …
```

해당 사항이 없는 줄은 `없음`이라고 쓴다.
